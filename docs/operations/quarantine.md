# Reference normalization and quarantine

Hades-010 implements a localhost development slice: raw HTTP ingress → embedded
Bento 1.22.0 Bloblang → contract/context validation → bounded volatile queue →
MQTT 5 QoS 1. The engine imports only the public Bloblang package, not Bento's
connector registry. The trusted mapping is compiled once in a pure environment,
with imports disabled. New acquisition IDs are never generated by mapping.

Run the broker as described in [MQTT development](../tutorials/mqtt-development.md),
then run:

```sh
go run ./cmd/hades-normalizer
curl -i -H 'Content-Type: application/json' --data-binary @examples/raw-observations/valid.json http://127.0.0.1:8081/observations
./scripts/smoke-normalization
```

Raw input uses the exact envelope fields in the fixture, replacing `measurements`
with `signals.temperature`. Require explicit numeric/null value, `deciCel` unit,
and quality. The checked-in reading mapping renames temperature to
`motor_temperature`, multiplies non-null values by 0.1, and declares `Cel`.
Identity, source (including full-precision sequence), observation and ingestion
timestamps are copied unchanged. Units are checked before conversion. Contract
and the locally approved metadata revision are checked after mapping. This is
one configured simulator asset; read-only industrial acquisition remains Hades-015.

Ingress returns 400 for invalid wire JSON, 413 above 65,536 bytes, and 422 for
mapping/context failures. These create private diagnostics and never publish
normal telemetry. `202` with `acceptance: accepted_broker_ack` requires successful
MQTT PUBACK; entering the bounded memory wait queue does not acknowledge gateway
ownership. Pending/in-flight waits share limits of 4,096 records and 16 MiB,
charging payload plus 4 KiB bookkeeping per record. Capacity and publication
timeouts return 503/Retry-After: 1. The gateway retains immutable bytes through
these failures. `/health` exposes wait occupancy, publication and HTTP broker-ack
counts, failures, refusals and diagnostic eviction counters. See
[ingress acknowledgement](ingress-acknowledgement.md) for the remaining broker and
volatile gateway acquisition failure boundaries.

Quarantine is a single-owner mode-0700 directory with mode-0600 records. Each
synced record contains a bounded reason, HTTP status, receipt time, base64 payload
prefix and truncation flag. Oversized bodies capture only the first 65,536 bytes;
the full original body is not retained. There is no HTTP payload-reading endpoint.
Only the local service account/operator may inspect files. Do not put credentials
in industrial payloads. Bind HTTP and MQTT to loopback until Hades-016 supplies
production identity and access controls.

Limits are 10,000 records / 64 MiB, including serialized overhead plus 4 KiB per
record. Oldest diagnostic keys are evicted at capacity with a counter. Storage
reserves at least 128 MiB free space before writes; failures return 503 and log a
bounded storage error. Directory/file fsync and atomic rename establish the file
store boundary, assuming the filesystem honors sync. Corrupt records, unexpected
files, permissive directory permissions and a second process owner fail startup.
Free-space checks do not reserve physical blocks against other processes; pilot
host allocation and storage failure drills remain Hades-017/022.

Verification: `go test -race ./internal/normalize ./internal/storage` covers
mapping, null/quality preservation, unit/type rejection, admission/backpressure,
retry, sync/reopen, exclusion, capacity and corruption. `scripts/smoke-normalization`
compares actual MQTT outputs and quarantine counts for the required fixtures.
The native macOS run passed using Mosquitto 2.1.2; the workflow repeats against
the pinned broker on Linux. No local Docker execution is claimed.
